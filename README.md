## 五、发现的 5 个缺陷

| 编号 | 缺陷 | 严重程度 | 类型 |
|---|---|---|---|
| **BUG-001** | 门店营业状态接口返回 500，前台无法显示营业状态 | **2-严重** | 接口 / 序列化 |
| **BUG-002** | 超长连续字符导致页面布局被撑破（1280px → 13669px）| 3-一般 | 前端排版 |
| **BUG-003** | 标题为空时页面顶部留下 150px 空白区域 | 4-轻微 | 前端排版 |
| **BUG-004** | 修改人物信息后，博客列表因片段缓存未失效仍显示旧名 | 4-轻微 | 缓存一致性 |
| **BUG-005** | 后台侧边栏与主列表点击页面标题行为不一致，无子页面时显示空白面板 | 4-轻微 | 交互一致性 |

### 几个值得说明的点

**BUG-001（接口 500）**
通过分析前端 `location-status.js` 中的防御性检查
（`typeof data.is_open !== 'boolean'`）反推出接口可能异常，
最终定位到 `locations/models.py` 中 `APIField("operating_days")` 缺少序列化器。
**影响全部 6 个门店页面。**

**BUG-002（排版溢出）**
将"排版是否被撑破"这一主观判断，转化为可断言的客观指标：

```python
document.documentElement.scrollWidth > document.documentElement.clientWidth
```

实测标题 200 字符时页面宽度达 **13669px**（视口仅 1280px）。

**BUG-004（缓存一致性）**
通过对比「已缓存的旧服务进程」与「全新启动的服务进程」，
证明数据层正确、问题出在模板片段缓存
（`{% wagtailcache 500 posts tag %}` 的缓存键不含 Person 数据）。

**BUG-005（交互一致性）**
在手工探索中发现：同一个页面，从侧边栏进入与从主列表进入，
跳转地址不同（`/admin/pages/34/` vs `/admin/pages/34/edit/`），
导致无子页面时看到空白面板。

## 六、自动化测试体系

四套自动化，分别覆盖不同层面的测试需求：

### 1. 前台 UI 自动化（pytest + Playwright）

```
cd 自动化测试/pytest套件
pip install -r requirements.txt
playwright install chromium
python -m pytest
```

- **19 条用例**：首页/导航/404、面包列表与详情、搜索 6 类场景、表单校验、响应式、缺陷回归
- 采用 **Page Object 模式**（6 个页面类）
- **缺陷回归**：门店营业状态用例标记为 `xfail`，BUG-001 修复后会自动转为 XPASS 提醒更新
- 失败自动截图，生成 HTML 报告

### 2. 数据驱动执行器（Django ORM + Playwright）

`自动化测试/数据驱动执行器/`

后台管理界面的 UI 自动化维护成本高，因此改用 **ORM 直接改数据 + Playwright 验证前台** 的方式：

```
① 备份数据库
② 程序修改数据（等效于后台操作）
③ Playwright 打开前台做断言
④ 自动恢复数据
```

- 三批共 **43 条**用例：数据同步、发布状态、缓存、搜索、边界、关联数据、版本回滚、表单后台验证
- 每个用例执行前后自动备份/恢复，**不会污染数据**

### 3. 弱网测试（Playwright CDP 网络模拟）

`自动化测试/弱网测试.py`

通过 Chrome DevTools Protocol 精确模拟网络环境：

```python
cdp.send("Network.emulateNetworkConditions", {
    "offline": False, "latency": 400,
    "downloadThroughput": 400 * 1024 // 8,   # Slow 3G
    ...
})
```

**7 条用例**，实测数据：

| 网络环境 | 首屏耗时 |
|---|---|
| 不限速 | 0.09 s |
| Fast 3G | 1.95 s |
| Slow 3G | 7.04 s |

### 4. 性能测试（Locust）

`自动化测试/性能测试.py` + `locustfile.py`

**逐步加压 5 → 10 → 20 → 40 并发**：

| 并发 | P95 响应 | 吞吐 | 错误率 |
|---|---|---|---|
| 5 | 52 ms | 2.46 RPS | 0% |
| 10 | 100 ms | 4.80 RPS | 0% |
| 20 | 220 ms | 9.42 RPS | 0% |
| 40 | 480 ms | 18.53 RPS | 0% |

> ⚠️ **说明**：被测对象是 Django 的 `runserver`（开发服务器），
> 以上数据仅作为**本地基线**，不代表生产环境承载能力。

## 七、测试工具（自研）

| 工具 | 用途 |
|---|---|
| `验证助手.py` | 手工测试的"半自动"伴侣：一条命令检查页面标题/文字/元素数/横向溢出；**检查失败自动截图、通过则自动恢复数据** |

## 八、环境准备

```bash
# 1. 克隆被测项目
git clone --depth 1 https://github.com/wagtail/bakerydemo.git
cd bakerydemo

# 2. 创建虚拟环境
python -m venv .venv
.venv\Scripts\Activate.ps1      # Windows PowerShell

# 3. 安装依赖
pip install -r requirements/development.txt

# 4. 初始化
cp bakerydemo/settings/local.py.example bakerydemo/settings/local.py
cp .env.example .env
python manage.py migrate
python manage.py load_initial_data

# 5. 启动
python manage.py runserver
```

访问 `http://127.0.0.1:8000`（前台）与 `http://127.0.0.1:8000/admin`（后台，admin / changeme）。

## 九、踩过的坑

| 坑 | 说明 | 解决 |
|---|---|---|
| **Django + Playwright 同步 API 冲突** | Playwright 内部有异步事件循环，Django 会拒绝在异步上下文中访问数据库 | 设 `DJANGO_ALLOW_ASYNC_UNSAFE=true` |
| **CDP 限速的"不限速"参数** | `downloadThroughput: 0` 实际是 0 字节/秒（比 Slow 3G 还慢） | 必须用 `-1` 表示不限速 |
| **恢复网络要复用 CDP 会话** | 每次 `new_cdp_session` 会残留旧的离线设置 | 复用同一个会话对象 |
| **Wagtail 草稿机制** | `page.save()` 直接改数据库；`save_revision()` 才是存草稿 | 按测试目的选择 |
| **改 slug 会自动创建重定向** | 可能污染测试数据，甚至形成重定向循环 | 测试后清理 `Redirect` 表 |
| **Playwright 的 `goto` 默认跟随 301** | 测重定向时拿到的已是最终状态码 | 用 `response.url` 判断或禁用跟随 |
| **Dev server 的性能结论有限** | `runserver` 不是生产服务器 | 只作为本地基线，不下生产结论 |
